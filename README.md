# IT-Engineering-Portfolio
## What is this repo?
While learning system engineering, I wanted to learn how things are built and make actually deliverable solutions. This is my best effort to do so.
This is a set of realistic IT systems integrations, from end to end.

While all of these are invented from scratch, I intend to invest in research and make them as realistic as possible.

## Why?
There are four main reasons I think this project can be of great benefit:
1. I will have a CCNA exam in June (as I am writing this is the 29th March 2026) and after that I will aim at RHCSA. This is a great way to practice the things I am learning.
2. I think this project is great to increase my employability and independence. Also, I think i will learn a lot in terms of project management. 
3. If done well and in details, I am sure this project will help others.
4. It's exciting and fun.

## Naming and navigation
Every folder is a distinct project. The naming convention i chose is
  `number - infrastructure type - operation - business sector`

While one of the downsides is occasionally a longer name that acceptable, I think that it delivers clear ideas to the reader regarding the project itself.

## Project contents
In every project folder you will be able to find a README.md at the root of the project.
The objective of that README is to explain what the project is about. More details about the context of the project are found in the `context` folder.

```
|.
├── context                 # Specs definition, budget, real prices, floor plans, images, it requirements
├── infrastructure          # Implementation of hardware. From cabling to choices of endpoints.
├── configuration           # every OS, tablet, phone, network device, AP etc. 
├── src                     # Every additional tools that requires software.
├── security                # security analysis and implementation
├── testing                 # Every testing done on code and infrastructure
├── monitoring              # monitoring tools for everything
├── backup-and-recovery     # procedure implementation for back and disaster management
├── docs                    # documentation that will be delivered to the client
└── README.md
```
